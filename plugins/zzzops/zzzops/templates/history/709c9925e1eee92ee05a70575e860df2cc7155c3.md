# Implement

Implement the design so that the accepted tests pass, on the goal's work branch (your card's `workspace`).

- Never change the accepted tests (frozen paths are refused at submit). If a test is wrong, do not edit it: submit a finding on `test_design` that explains why, and continue with what you can.
- Commit normally. Run every command in `commands_to_run` in the workspace before you submit, and fix what fails.
- Put a 2–4 sentence summary of what you built in `summary`: it is shown to the human for the merge decision.
- Your checkpoint defaults to the suggested checkpoint in the card, else your work branch's HEAD; omit the key unless you override.
- If you are answering findings, answer every one in `responses` with `fixed: …` or `disputed: …`.
- Notes are optional: act on one only if it is cheap and in scope.
- If you meet a risk that a skipped lens covers, submit `--blocked` with the options `unskip <node ids>` and `continue`.
