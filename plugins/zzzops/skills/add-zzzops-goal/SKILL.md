# Add ZzzOps Goal

Run `../../rules/INITIALIZATION.md`, then `../../rules/BACKENDS.md`. Use minimal discovery for duplicate/relationship checks; hydrate only likely matches, and comments only when current intent is insufficient. Before writing, classify evidenced risk categories, persist only those inputs and an authorized override, then run an adaptive requirements interview at the portfolio's effective engineering rigor. Map `vibe → light`, `structured → standard`, and `agentic → thorough`; this is the sole capture-depth control. Legacy policy uses its reviewed `requirements_interview.capture_depth`, or `standard` when absent. Automatically escalate when policy and evidence require it; never silently de-escalate or undercut a risk minimum.

Reuse the request, repository evidence, related goals, and prior answers. Ask only consequential gaps, 1–3 at a time, recommending material choices; never repeat answered or irrelevant dimensions. `light` establishes outcome, observable acceptance, and critical constraints. `standard` also checks scope/non-goals and material examples, dependencies, risks, authority, and verification. `thorough` additionally checks applicable architecture, security, data lifecycle, failure/recovery, operations, rollout, accessibility, compatibility, and governance. Challenge subjective success and contradictions. The current user is the sole stakeholder and acceptance owner; multi-party discovery/sign-off is out of scope.

When unfamiliarity or decision risk could change architecture, scope, acceptance, or quality, run a bounded blind-spot pass for known unknowns, tacit criteria, and blind spots. Use the cheapest useful reference, research, alternative, or disposable prototype. Skip well-understood work and fixed ceremony.

Stop when independently actionable and verifiable at that depth, or remaining unknowns are explicit blockers. Create one human-first canonical goal with current schema label. Capture applicable source location and value evidence; never invent answers. Use `$execute-zzzops` afterward.

Capture never creates a branch, commit, push, PR, or empty Git checkpoint.

Apply `../../rules/CONTINUATION.md`; active same-task execute intent may resume once, while capture-only/replacement/stop wins. Confirm outcome/link and only next-affecting relationships or unknowns.
