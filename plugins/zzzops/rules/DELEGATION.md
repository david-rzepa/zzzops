# Delegation

Eligible isolated work must be delegated within allowed capacity: two independent tasks or one beneficial long/context-heavy task.

Before declaring delegation unavailable, inspect the complete runtime catalog, including deferred tools (in Codex, filter `ALL_TOOLS` for delegation, worker, sub-agent, and agent terms); the visible list alone is insufficient. Record the capability state and evidence.

Every delegated launch first produces a phase routing decision with explicit `model` and `effort`, compared with the root pair and validated before launch; omission or implicit inheritance is invalid. Root-equivalent work runs directly on the root; above-root capability requires the reviewed session override.

Skip for authority/safety, conflict/coupling, triviality, or overhead; record why. If no eligible work exists, sequential execution is valid. If eligible work requires delegation and the complete catalog exposes no launch capability, report an actionable harness-capability blocker rather than silently falling back.

Assign scope/resources/probe/prohibitions/stop; return concise evidence-linked summaries, never transcripts. Only the coordinator owns state/claims/reservations/integration/decisions/external writes/approvals/user communication. Read-only never write; writable work requires disjoint worktrees under `EXECUTION_STRATEGY.md`.
