# G1050 implementation review

The implementation passes the submitted checks but does not yet safely handle two real true-to-false route transitions. I reproduced both on the submitted code with the actual ZzzOps CLI and isolated local bare remotes.

1. **A downstream finding can be bypassed.** `engine/frontier.py` checks open findings only inside the records for nodes in `members`. A completed `test_design` can raise an open finding targeting `scaffold` (the approved design explicitly directs test authors to do so). After a design re-review flips `scaffold_needed` from true to false, the finding remains open in `test_design`, but both `scaffold` and `review_scaffold` become skipped and `test_design` becomes ready. The guard must account for active material findings targeting those nodes regardless of their carrier, without silently invalidating evidence. A real CLI probe created a reviewed scaffold, submitted the downstream finding, changed the route and observed exactly those states.

2. **Blocked scaffold code can bypass review.** The same guard only looks for completed or `last_output` checkpoints in scaffold records. A scaffold agent can commit work, then submit blocked; that publishes the work branch while the record has no output checkpoint. A subsequent true-to-false route transition skips both scaffold and its independent review and offers `test_design`, leaving that committed scaffold code in the work branch without any independent review. I reproduced this with the real CLI by committing scaffold code and submitting a `waiting_for: agent` blocked result before changing the route. The transition must preserve and verify blocked-attempt scaffold work or require an independently reviewed removal, not infer that no work exists from a missing output checkpoint.

The measured focused suite ran 34 real Git/CLI tests in 71.6 s, with a focused child-preservation test in 1.47 s. That cost is appropriate for the behaviors tested; neither above transition appears in the suite. The migration fixture is specifically for safe in-flight policy adoption and is not an obsolete parallel-workflow test retained for its own sake.
