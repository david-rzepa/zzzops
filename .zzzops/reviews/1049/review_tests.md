# G1049 fencing tests, attempt 7

The revised suite meaningfully addresses the prior findings: the competing process must now reach a server push or explicitly refuse before the held writer is released; gate namespace is no longer artificially constrained. It adds real-remote tests for held-gate start, base, workspace output/blocked submission, independent artifact submission, existing live publisher, TTL, expired-holder refusal, crash and reclaim. The writer measured the full 25-test pair at 170.973 seconds and the five added lifecycle/writer cases at 28.176 seconds pre-implementation. I independently ran the existing-publisher case (5.585 s); it stops at the not-yet-implemented recovery diagnostic, so this is red setup evidence, not proof that fencing or barriers pass. The costs merit a post-implementation green measurement, but real concurrent Git operations are justified.

One required safety boundary is still absent. The approved design requires a shared pre-push guard covering every atomic work-ref update, including unknown future callers, and specifically requests a lower-level test for an unlisted writer. The added tests call only the known start, submit, artifact, base and edit routes. The pre-existing `store.push_atomic(git, R, updates)` accepts neither settings nor gate context, so a meaningful executable test requires a defined testable guard seam or a dummy operation invoking the eventual guarded transaction API. A test that merely asserts a list of known routes would not prove the guard. Also ensure a real operation-completion update for the work ref and successful gated paths receive coverage.
