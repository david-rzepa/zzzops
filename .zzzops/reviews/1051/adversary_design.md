# Adversarial re-review: G1051 snapshot verification

Changes requested. The revision correctly acknowledges that a goal-record CAS cannot atomically compare unchanged Git refs, and specifies atomic expected-old checks on each actual destination write. The prior claim of cross-ref atomicity is resolved. One remaining testable contradiction needs correction.

Suppose production advances immediately after the final observation but the isolated patch-line ref does not change. A subsequent write to that patch line using the previously observed patch-line SHA as the expected old value can succeed: the patch destination still matches, even though production moved. A per-destination Git CAS does not compare a different production ref. The design's test strategy nevertheless requires that, after this interleaving, *all* actual destination-ref updates fail their expected-SHA guards until fresh approval. That guarantee does not follow from the proposed protocol, and a test cannot prove it honestly against the real remote.

State which safe behavior is intended: for example, permit isolated patch-line updates as speculative work on the approved immutable base while requiring refreshed classification and atomic comparison before any production update, or require a genuinely atomic cross-ref guard where stricter semantics are necessary. Align the narrative and race assertions with that choice. Test the precise interleaving: production alone moves after the last check and before an unchanged patch-line destination is pushed; distinguish it from a moved patch-line destination and from an attempted production update. No claim of external-ref movement auditing is needed.
