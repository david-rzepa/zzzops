The contract says to reread production and the created line, then use a CAS-protected **goal-state** update to mark the line verified only if production and the line still match the approved values. An external actor can advance production or alter the line after those reads but before the goal CAS. The goal CAS does not compare either remote ref, so it succeeds and releases the member-work gate despite the change occurring before verification. This directly contradicts the requirement to leave the line pending if either ref changes across that window. The baseline engine's atomic push updates only the goal and newly created line refs, and its internal leases do not serialize direct production pushes. A later production-write CAS is important but does not stop members from starting on the prematurely verified line.

Do not promise that a goal-only CAS observed independent refs atomically.
