One material test defect remains. In `test_source_revoked_during_protected_finish_records_merge_and_pauses_forwarding`, the expected-PR-head assertion searches **all** `self.gh.calls()` without taking an offset or filtering for the actual finish PR. That history already contains merges from `finished_source()` and `self.done(patch)`, which in the current engine use `--match-head-commit`. A new finish implementation could omit its own required expected-head guard, merge a changed PR head, and still satisfy this assertion using a setup merge. The member-merge changed-head case protects a different operation and does not prove the release-finish guard. Capture and inspect only the actual finish PR's provider call and verify its expected head matches the approved finish head; add or adapt a provider-boundary race that changes that finish PR head after precheck and proves no unapproved head is merged. This needs no live provider or new production interface.
