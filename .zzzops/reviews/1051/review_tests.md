# G1051 maintenance forward-port test re-review

The three previous findings are resolved. Head-only and destination-only changes are now tested separately while holding the other ref constant, requiring fresh approval and no stale merge. Source-goal-only and destination-only changes are injected independently at the fake provider merge boundary; the tests check the actual merge result, ancestry, no production rollback and a paused human item. The design correctly acknowledges the independent-ref race rather than claiming atomic prevention.

The fixture-cost correction creates the two-release history with the actual engine once per class, then physically copies its bare Git remote and provider state to independently bootstrapped per-test fixtures. Each copy checks its initial ref set and uses a distinct remote. The exact-checkpoint focused run is 39.478 s for 15 cases, down from 176.707 s for 12 previously. The class setup is included in total wall time. Three existing dispatch/pending cases pass; all 12 new maintenance cases fail at the missing CLI before reaching their assertions. This is red pre-implementation evidence, not proof of the forward-port behavior. Fake GitHub does not establish hosted branch-protection behavior; the design keeps staging as a separate gate.

One material no-diff coverage gap remains. `test_equal_trees_without_lineage_or_matching_pr_are_not_proof` says it makes equal trees, but it only adds `src/maintenance.py` to the newer dev branch. That branch retains `src/newer.py`, which is absent from the maintenance source. I independently ran this exact fixture: source tree `8763a8815672c8ba3d4c21b2653c832c0e32749d` and destination tree `7254c1b7d5240d810cb1f61a33de0b3c615972ea` differ, and the source is not an ancestor. The fake-provider wrapper unconditionally reports no diff, so a faulty implementation that incorrectly treats truly equal trees without ancestry as proof could still pass this case. Construct two genuinely equal Git tree objects with divergent ancestry, assert tree equality and non-ancestry before requesting the forward-port, then require `no_diff_unproven` with no fabricated merge or destination change. Retain the provider refusal case and real isolated Git; no hosted service or new implementation interface is needed.
