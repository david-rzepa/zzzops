# G1051 durable regression test review

The external-merge tests create a genuine release line and approved synced tip, then move and merge an unapproved PR head either before the provider view returns or before recovery. They verify the actual merged head and merge commit, production ancestry, retained evidence and paused propagation rather than claiming the external merge was prevented.

The nested maintenance test starts from real completed releases and explicitly requires multiple unpublished intermediate commits; it verifies the proposed source and released ancestor against actual Git ancestry without moving production. The historical-snapshot cases create real goal objects for missing, contradictory and self-referential source snapshots and call the real lineage validation in a local Git session. The negative cycle case is a targeted check on an actual implementation boundary, alongside the real CLI/Git nested journey; it is not presented as a hosted-provider test.

I independently ran the four exact-checkpoint cases at `da22933`. Three passed; the logical source-goal cycle was accepted and failed its expected rejection, in 36.807 seconds including the genuine shared release seed. This agrees with the reported 36.877-second red observation. The result does not establish the full suite, published artifact or hosted GitHub staging gate. The measured cost is proportional to the two separate real release-finish/provider scenarios and the shared maintenance seed; no new material test findings.
