## Outcome

Prevent goal work from being treated as durably saved while it remains purely local. The CLI must ensure that referenced work branches are present on the intended remote and contain the referenced work, reducing loss risk if a local checkout or machine disappears.

## Acceptance criteria

- [ ] Identify all CLI-owned goal/workflow/evidence references to work branches and define the durability checkpoints where validation is mandatory. A branch name existing remotely is insufficient: verify that the referenced commit/work is reachable from the intended remote branch.
- [ ] Use fresh authoritative remote observations at durability checkpoints rather than trusting local tracking refs, configured upstreams, stale cache or a successful push exit alone. Bind evidence to repository identity, remote, branch and exact referenced commit.
- [ ] Do not accept a local-only reference or report durable handoff/publication/completion when the remote branch is missing, behind or unrelated. Reject before dependent canonical mutations where possible; retain recoverable state and precise guidance naming the missing branch/commit and required action.
- [ ] Preserve normal local editing while work is in progress, but require remote durability before a referenced work checkpoint is accepted as saved or handed off. Include named prototype/work branches when referenced; explicitly distinguish uncommitted/unreferenced work that branch validation cannot protect.
- [ ] Respect existing remote/branch and push authority. Do not invent a remote, expose private work to another repository, force-push, overwrite/delete refs, or silently change stack bases. If authorization, authentication or connectivity prevents verification/push, report the blocker without claiming durability or losing local work.
- [ ] Cover new branches, unpushed local commits, stale tracking refs, wrong remotes, diverged/rewritten/deleted remote branches, stacked branches, lost push responses and retries. Ensure repeated verification is idempotent and the correct already-published reference passes.
- [ ] Add public CLI regression tests for the validation boundaries and actionable diagnostics, plus a controlled local bare-remote integration test demonstrating recovery of accepted referenced work from a separate clone. Avoid unnecessary network requests through bounded batching/caching without weakening the authoritative checkpoint checks.

## Scope

This goal is a durability invariant for referenced work, not blanket automatic commits or permission to publish secrets/unrelated dirty files. Decide the narrowest implementation and whether an existing authorized publication operation pushes or only requests a push during understanding. No merge/release authority is granted. It is separate from the token-ledger goal.
