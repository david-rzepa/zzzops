## Outcome

Checkpoint and lease renewal can read complete GitHub comment history within their overall operation deadline, without failing prematurely at a shorter fixed subprocess timeout.

## Observed failure and reproduction

On goal #498, the installed public execute checkpoint and same-worker renewal raised TimeoutExpired at the provider adapter's fixed 30-second subprocess cap. A cumulative 90-second renewal budget did not extend that individual comment read. A direct authenticated paginated read returned all 332 comments (100, 100, 100, 32) but took more than 30 seconds. An administrative harness extended only the exact comment-pagination GET timeout within a finite deadline; the unchanged public same-token renewal then returned renewed. This mitigation is not a permanent production fix.

## Acceptance criteria

- A deterministic slow, multi-page provider regression fixture reproduces the premature 30-second failure before the fix and proves successful complete history reads when the overall operation deadline permits them.
- Checkpoint and renewal propagate a bounded overall deadline to comment-history reads; a shorter fixed subprocess cap cannot prematurely defeat a permitted read. Actual deadline exhaustion terminates predictably.
- Preserve every history record and required ordering and validation. Partial pages, malformed responses, and failed reads must never be accepted as complete current evidence. No truncation, compaction, or restriction on targeted historical reads is required by this goal.
- Timeout diagnostics identify the affected goal/read and provide an actionable supported retry. Timeout or expiry alone grants no lease takeover or assumed success.
- Retry preserves exact worker/lease ownership and existing write fencing and idempotency; controlled tests cover successful delayed reads, genuine deadline exhaustion, and partial/provider failure without duplicate updates or lock leaks.

## First falsifiable probe

Use the real public checkpoint and renewal paths with a synthetic authenticated provider/subprocess fixture returning four delayed comment pages. Demonstrate that a read exceeding 30 seconds but fitting the operation deadline currently fails. Keep test timing deterministic and avoid depending on live GitHub latency.

## Scope, relationships, and authority

Capture only; production implementation requires the normal reviewed design, test, and execution gates. Choose deadline propagation, pagination, or caching mechanics during review rather than codifying the administrative workaround. Related #489 and #494 cover heartbeat liveness and storage recovery; this goal concerns the nested comment-read deadline affecting checkpoint as well as renewal. Related #515 concerns portfolio hydration. No dependency or parent relationship is asserted without investigation.

## Capture authorization

The user accepted the proposed scope (overall-deadline-aware pagination, clear diagnostics and safe retries, and a slow multi-page regression test) with: "Ok let's add that goal now". This authorizes capture only, not implementation design or priority over the main task.
