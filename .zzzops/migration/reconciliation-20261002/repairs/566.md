## Outcome

Let an agent request work on a (goal, workflow node/phase) and receive a CLI-prepared, isolated Git worktree at the current valid goal-tree checkpoint. ZzzOps owns phase-attempt commits, safe resumption, worktree cleanup and necessary rebases so agents no longer reconstruct historical file snapshots or repair branch order by hand. Git ancestry and file/content hashes remain evidence of the exact inputs and outputs; neither replaces goal, policy, provider or review authority.

## Acceptance criteria

- [ ] Add public prepare/status/finish/resume/abort operations for a goal and executable node/phase. Prepare acquires the applicable lease, resolves the latest accepted goal-tree commit and current non-Git evidence, creates or safely reuses a managed worktree, and returns its path, base commit/tree, allowed output paths, consumed inputs, worker identity, verification obligations and next command. Read-only review worktrees use the exact reviewed commit and cannot write shared goal state.
- [ ] A phase attempt starts from the latest valid goal tree, not a historical phase checkout. Record the acquired base commit/tree and relevant file hashes, the changed paths and output tree/commit, plus policy, goal, provider and review evidence revisions. Preserve drift detection for unrelated or concurrent changes, stale workers, wrong leases, scope violations and changed external inputs. Commit identity alone is not sufficient proof of valid work.
- [ ] During execution, the CLI stages only authorized outputs and creates a recoverable semantic commit for each verified attempt. It refuses unexpected staged, unstaged, untracked, deleted, generated or symlink changes outside scope with exact diagnostics; it never commits another checkout's dirt. Recording and Git commit use retry-safe receipts so a crash or provider failure cannot duplicate or lose an attempt. Existing agent-made commits may be adopted only after equivalent checks.
- [ ] Corrections preserve prior attempt evidence and normally create new internal commits at the current goal tip. Demonstrate T1 tests -> I1 implementation -> T2 corrected tests -> I2 corrected implementation: T2 runs red against I1, I2 runs green against T2, earlier review/evidence remains historical, and only affected current consumers rerun. Amend/rewrite of a published or reviewed commit never silently carries its approval to a new commit ID.
- [ ] Support independent writable workers in separate managed worktrees under reviewed parallel/resource policy. Only the coordinator integrates commits into the one goal/PR stack, using validated ancestry, ownership and deterministic order. Detect conflicting outputs or moved tips before integration; do not assume a path declaration proves which process wrote a file. Coordinate with #532 for remote stack integration and exact-head publication checks.
- [ ] Declare workspace preparation, commit boundaries, attempt retention and publish-time grouping through reviewed generic DAG node/action contracts. A project can choose which accepted outputs form separate bounded published commits and which correction attempts compact together; the CLI validates these declarations and applies one unchanged mechanism without hardcoded test_design/implement rules or an arbitrary Git scripting language. DAG revisions after work has started preview affected commits, evidence and review obligations, require applicable approval, and never silently erase an unresolved finding or rewrite accepted history.
- [ ] At publish, synthesize the candidate history according to the reviewed DAG grouping: squash intermediate retries that are valid only together, while retaining separate commits for independently useful bounded commitments. The PR branch should present the final changes, not every failed attempt. Preserve the complete attempt/verification/review transaction history with immutable provenance and a retention mechanism sufficient to inspect old code or patches even if transient Git refs are pruned; do not rely on unreachable local commits. Bind required final verification, independent review and exact-head CI to the compacted candidate. Show the before/after commit plan and evidence invalidation before rewriting any already published branch; remote publication remains gated by existing authority.
- [ ] Manage required rebases when safely deterministic. On conflict, stop in a durable state and return the managed worktree path, conflicted files, allowed resolution scope and exact continue/abort command. After agent resolution, recheck lease, base, scope, conflict completion, resulting tree and affected evidence before continuing. Abort restores the preserved pre-rebase attempt. Published/reviewed history and force-push authority remain separately gated; no automatic semantic conflict resolution.
- [ ] Preserve dirty or interrupted attempts before cleanup with a durable private ref/snapshot and recovery receipt; never force-delete unpreserved work. Resume after process/coordinator crash, expired lease, uncertain Git/provider response or a later worker without duplicating live work or granting stale authority. Remove only confirmed clean managed worktrees after a committed/parked terminal transition; leave ordinary user worktrees untouched.
- [ ] Validate the full local goal stack before record, compaction, push, publish or integration. Auto-repair only deterministic safe layout errors; otherwise block with the exact divergent commits/files/evidence and a recovery action. External branch movement, out-of-band commits, concurrent merges and incompatible policy/goal revisions cannot silently pass. A local commit is not remote proof; require current remote branch/PR evidence at publication.
- [ ] Provide public-CLI integration tests using disposable Git repositories for initial preparation, legitimate phase return, independent workers, conflict/continue/abort, dirty interruption, publish-time compaction with retained provenance, crash at each commit/record boundary, changed non-Git inputs, moved local/remote heads, stale reviews, scope violations and idempotent retry. Assert the intended tests actually ran and distinguished assertion failure from import/runner failure, coordinating with #557 rather than duplicating its verification engine. Measure worktree/commit/provider overhead against the current manual path.

## First falsifiable probe

In a disposable repository, commit T1 and I1, then request test_design again. The current workflow requires manual reset/reconstruction or rejects a valid T2 because its recorded source snapshot predates I1. Prototype only the prepare/finish boundary: create a managed worktree at I1, commit T2 containing only reviewed test paths, and prepare implementation at T2. Assert T2 red tests execute by intended IDs against I1, I2 green tests execute against T2, and a changed unrelated input or out-of-scope file is rejected. No production implementation before independent design review of the exact state/commit contract.

## Relationships, decisions and boundaries

Depends on #497 owned input/output evidence and #499's final generic node topology (which depends on #498). Coordinate, without absorbing their work, with #500's real-edit regression, #532 remote stack integration, #550 worker transport and #557 verification plans. This goal owns generic DAG-declared local workspace/commit preparation, publish grouping and recovery, not a second workflow DAG or test runner. Keep one active stack and current project Git/review authority. Do not auto-push, force-push, merge, release or approve from a local workspace transition.

The requested direction is DAG-configured CLI-managed worktrees, recoverable local attempt commits, DAG-configured compact published history, safe rebases with agent-resolved conflicts and exact resume commands. Capture assumes one goal with staged bounded delivery, preservation of reviewed history, and durable preservation before dirty-worktree cleanup; these are explicit proposal choices for human review. Risks include Git/provider non-atomicity, evidence invalidation, branch fan-out, parallel ownership, conflict semantics, private-ref retention and unbounded workspace accumulation. Review these against simpler guidance-only or commit-only alternatives and define a bounded garbage-collection policy before implementation. Capture does not authorize implementation, publication or policy change.
