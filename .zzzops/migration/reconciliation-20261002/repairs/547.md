During normal execution, human-only questions must block only affected work while agents continue eligible autonomous work.

- [ ] The add-goal skill interprets the request and prepares initial discovery questions before creation. The initial published goal already contains those questions, a durable discovery reservation and an acquired lease for the capturing agent. There is no observable creation-to-reservation gap in which another agent can dispatch normal execution.
- [ ] The capturing root immediately continues the adaptive interview through specification synthesis, independent applicable reviews and required human approval rather than returning after issue creation. Further questions can arise during synthesis or review; approval binds current reviewed evidence.
- [ ] Discovery is the umbrella for requirements, spec, spec_review and approval. Requirements owns durable questions, answers, decisions and unresolved points, with identity and provenance; specification and review reference applicable revisions. Use generic configurable nodes and evidence rather than hardcoding this topology into the engine; coordinate #499's default naming/topology.
- [ ] Distinguish durable capture eligibility from temporary lease ownership. If the human stops responding or the agent exits, persist progress, mark waiting for human, and permit lease release/expiry without making the goal executable. Explicit authorized capture recovery can acquire ownership and resume unanswered questions without repeating settled answers or losing valid specification/review evidence.
- [ ] Questions declare human-only resolution authority explicitly, not merely root-agent assignment. Record the decision blocked and affected evidence/work. Agents must not manufacture answers or treat lease expiry as approval; technical questions resolvable within existing authority remain autonomous.
- [ ] Only completed, approved discovery releases the capture reservation into normal execution eligibility. Concurrent readers, stale workers, retries and partial provider writes cannot bypass this rule. Implement provider-realistic retry-safe publication/recovery rather than claiming multi-write GitHub atomicity; coordinate #542 capture idempotency.
- [ ] During execution, persist unanswered human-only questions and continue other eligible autonomous nodes/goals, including independent work within the same goal where dependencies and authority permit. Preserve goal priority for resumption instead of permanently demoting it. A human-waiting goal, approval step or broad discovery/understanding gate must not stall unrelated runnable work.
- [ ] Goal-scoped execution returns an explicit safe portfolio-continuation handoff when human-blocked rather than implying the entire portfolio must stop; respect an explicit user restriction to that one goal. At actual autonomous exhaustion report outstanding human questions distinctly from completion; do not poll the human or repeatedly ask during unattended execution.
- [ ] Verify through public CLI journeys: two agents racing creation/claim; initial questions and lease visible together; interruption mid-interview; expired lease and explicit recovery; stale-owner writes; uncertain create responses and retry; questions introduced by spec and review; exact-evidence approval/release; and a higher-priority human-blocked goal allowing lower-priority autonomous work. Include broad-phase and approval scheduling regressions and affected/unaffected evidence preservation.
- [ ] Update capture/execution prompts and explain capture versus execution interaction semantics. Preserve existing policy/approval authority and avoid unnecessary provider requests or new orchestration primitives where the generic contracts suffice.
