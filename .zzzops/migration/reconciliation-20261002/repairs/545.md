## Outcome

Record token usage prospectively in the activity ledger so a subsequent agent can inspect goals and analyze usage by goal, phase, attempt and participating agent/thread. User explicitly selected forward collection only: no historical backfill.

## Acceptance criteria

- [ ] Collect new usage after activation and associate it with durable goal, phase and attempt identities, agent/thread identity and parent relationship, observed model/effort and time boundaries where available. Preserve unattributed or missing data explicitly rather than inventing attribution or zero usage.
- [ ] Record available input, cached-input, output and reasoning-output token counts with clear inclusive/subset semantics, preventing double counting. Distinguish direct worker usage from phase/goal rollups including delegated work, retries and corrections.
- [ ] Use observed Codex usage events or persisted session records through a bounded provider adapter; do not depend on an Omarchy UI or collect account-wide snapshots as if they were per-thread usage. Document supported versions, unavailable fields and attribution limits.
- [ ] Make ingestion replay-safe across duplicate events, cumulative snapshots, reused workers, resumed threads, counter resets, compaction, partial records and interruption. Define authoritative event identity/boundaries and test overlapping root/worker activity without double attribution.
- [ ] Persist bounded, machine-readable usage evidence through the activity ledger and expose public CLI reads/aggregation so a subsequent agent can analyze per-goal and per-phase usage with provenance, completeness and gaps. Use batching/appropriate caching; do not add a backend write for every model event.
- [ ] Store only usage/attribution metadata needed for analysis, not prompts, transcripts, credentials or private session content. Token counts must not be represented as exact subscription allowance consumption or actual billed cost.
- [ ] Verify forward-only behavior and representative attribution/recovery cases with fixtures and a bounded real-session read-only comparison. Preserve normal execution when optional telemetry is unavailable, while visibly reporting incomplete metrics.

## Scope and evidence

Codex local session metadata observed in this side conversation includes agent_path and parent_thread_id; turn_context includes turn_id/model/effort; timestamped token_count events include last_token_usage and total_token_usage with token categories. The installed Omarchy collector already reads these events but rolls them up by model/day. Choose the smallest appropriate ledger representation during understanding rather than hardcoding storage now. This goal supplies metrics; it does not implement an optimization dashboard or modify Omarchy. Related but distinct: #502 classifier efficiency evaluation and #543 compact CLI input/output.
