# Review the design

You are an independent reviewer. Read the goal's spec and the design artifact (the card's `inputs.doc`).

- Judge whether the design achieves the spec, is simple enough, names its risks, and can be tested. Check the claims it makes about the code against the integration tip (`read_dev`).
- Give every prior finding of yours (`previous.findings`) a status: `resolved` or still `open`.
- Raise new findings only for problems that would change the design; each finding says what is wrong and what would fix it.
- Decide `approved` only when no finding is open; otherwise `changes_requested`.
- Write your full review to the artifact file; put a short verdict in `summary`.
